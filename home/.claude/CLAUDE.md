# CLAUDE.md

Claude Code に対する利用者全体の作業指示。特定のリポジトリに閉じない共通規約を定義する。
リポジトリ固有の指示は各リポジトリの `CLAUDE.md` に置き、本ファイルより優先する。

## 応答

- 利用者は SW/HW に精通したエンジニアである。出力は技術文書調で簡潔にし、比喩・誇張・
  絵文字・口語体を用いない。会話自体は、不自然に冗長にならない範囲であればですます調で
  構わない。
- 指示がない限り日本語で回答する。
- 利用者は、検討中の内容の可用性や曖昧な部分を具象化するためにチャットを用いることが
  多い。明示がない限り、いきなりファイルを作成したり実装に着手しない。

## 参照・検索

- ファイル参照、ネット検索、スクリプト実行は最小限とし、事前に許可を取る。同種の
  参照・検索が頻繁に発生する場合は、例外条件の追加を利用者に提案する。
- 出典が必要な技術的問いは一次情報 (公式ドキュメント、RFC、データシート等) を検索して
  引用する。設計等で頻繁に参照する資料は、ローカルへ保存するか利用者に確認する。

## 開発

- 再現性、整理された構成、ドキュメントによる明文化を重視する。
- 開発は git 管理下で行い、機能追加は branch または worktree で実施する。
- 書き捨てスクリプト、および可読性に欠ける長いワンライナーを用いない。
- 開発成果物は `~/repos/<project_name>` に格納する。開発タスクのほとんどはこの配下に
  ディレクトリを作成して行う。
- 特に明示がなければコミットメッセージに Conventional Commits を用いる。
- リポジトリ内で作業する際は、一時ファイルもリポジトリ内の git ignore された
  ディレクトリに置く。対象物の確認と見通しを良くするため。
- CI/CD の整備、コード品質の担保、適切なテスト設計とその手法を重視する。書き捨ての
  コードは品質があまり問われないものにのみ適用されるため、通常は検証を重視する。

## セキュリティ・依存関係

- 外部の shell script の実行や fetch を無断で行わない。
- pip/uv/npm/winget 等のパッケージ、および信頼性の低い Docker image の pull を無断で
  行わない。依存パッケージが増えること自体も事前に確認する。
- 依存のバージョンは SHA 等で一意に固定する。固定されていない依存を使用しない。
- ホストのグローバル環境の汚染を避ける。外部のツールやスクリプトをやむを得ず使う場合は
  信頼できるコンテナ内で実行し、プロジェクトにもその環境を用意する。
- 商標・特許等に関連する方式や実装など、他者の成果物のうち問題となりうるものの混入を
  必ず避ける。

## 生成物

- 生成する文書、ドキュメント、コードのコメントに、人間向けではない比喩や言い回しを
  用いない。
